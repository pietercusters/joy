2. Keep existing `_fetch_github_mrs` unchanged (returns `dict[(repo_name, branch) -> MRInfo]` filtered to active branches). Only add `reviewDecision,title` to the `--json` field list. Return type stays `dict[tuple[str, str], MRInfo]`.

3. Add `_fetch_github_authored_mrs(repo: Repo) -> list[MRDetail]`:
   - Calls `gh pr list -R {remote_url} --author @me --state open --json number,headRefName,isDraft,statusCheckRollup,url,reviewDecision,title --limit 100`
   - Returns `list[MRDetail]` with `is_review_request=False`
   - Map `reviewDecision` values: `"APPROVED"` -> `"approved"`, `"CHANGES_REQUESTED"` -> `"changes_requested"`, `"REVIEW_REQUIRED"` -> `"review_required"`, `""` or missing -> `None`
   - Same error handling pattern (raises RuntimeError on non-zero exit)

4. Add `_fetch_github_review_requests(repo: Repo) -> list[MRDetail]`:
   - Calls `gh pr list -R {remote_url} --state open --search "review-requested:@me" --json number,headRefName,isDraft,statusCheckRollup,url,reviewDecision,title --limit 100`
   - Returns `list[MRDetail]` with `is_review_request=True`
   - Same error handling pattern

5. Add `_fetch_github_branch_mr(repo: Repo, branch: str) -> MRInfo | None`:
   - Calls `gh pr list -R {remote_url} --head {branch} --state open --json number,isDraft,statusCheckRollup,url --limit 1`
   - Returns `MRInfo` for the first result, or `None` if no result / error
   - This is the per-branch fallback for worktree badges

6. Refactor `_fetch_gitlab_mrs` similarly: keep returning `dict[(repo_name, branch) -> MRInfo]` for `by_branch`.

7. Add `_fetch_gitlab_authored_mrs(repo: Repo) -> list[MRDetail]`:
   - Calls `glab mr list -R {remote_url} --author @me --output json --per-page 100`
   - Returns `list[MRDetail]` with `is_review_request=False`
   - Map `detailed_merge_status` to review_status: `"not_approved"` -> `"review_required"`, `"mergeable"` -> `"approved"`, `"discussions_not_resolved"` -> `"changes_requested"`, others -> `None`

8. Add `_fetch_gitlab_review_requests(repo: Repo) -> list[MRDetail]`:
   - Calls `glab mr list -R {remote_url} --reviewer @me --output json --per-page 100`
   - Returns `list[MRDetail]` with `is_review_request=True`

9. Add `_fetch_gitlab_branch_mr(repo: Repo, branch: str) -> MRInfo | None`:
   - Calls `glab mr list -R {remote_url} --source-branch {branch} --state opened --output json --per-page 1`
   - Returns `MRInfo` for the first result, or `None` if no result / error
   - Also fetches CI status via existing `_fetch_glab_ci_status` for the branch

10. Change `fetch_mr_data` signature to return `BatchMRResult`. Orchestration logic:
    - For each repo, call the appropriate `_fetch_{forge}_mrs` (unchanged, returns branch dict) AND `_fetch_{forge}_authored_mrs` AND `_fetch_{forge}_review_requests`
    - Each per-repo call is wrapped in try/except (existing pattern) -- partial results still returned
    - **Per-branch fallback (CONTEXT.md locked decision):** After all batch calls complete, compute `leftover_branches = active_branches_for_repo - set(by_branch_keys_for_repo)`. For each leftover branch, call `_fetch_{forge}_branch_mr(repo, branch)`. If result is not None, add it to `by_branch`. This ensures worktree badges work even when a branch's MR was not returned by the batch call (e.g., the batch returned only the user's authored PRs, or the batch hit a limit).
    - Aggregate all `by_branch` dicts, all `authored` lists, all `review_requests` lists into one `BatchMRResult`
