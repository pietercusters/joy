# Phase 20: Widget Tests & Snapshots - Research

**Researched:** 2026-05-08
**Domain:** Textual widget testing, visual snapshot regression, fake backend injection
**Confidence:** HIGH

## Summary

Phase 20 adds two complementary test layers to the joy TUI: (1) widget behavior tests using Textual's pilot with injected FakeBackend adapters instead of `@patch`-based mocking, and (2) SVG snapshot baselines for key screens using `pytest-textual-snapshot`. The codebase already has extensive pilot-based tests (`test_tui.py`, `test_worktree_pane.py`, `test_terminal_pane.py`) that use `@patch` for store/service isolation -- Phase 20 replaces that pattern with constructor-injected fakes conforming to the Protocol contracts defined in `ports.py` (Phase 18).

The main technical risk is a dependency conflict: `pytest-textual-snapshot==1.1.0` pins `syrupy==4.8.0` which requires `pytest<9`, but the project currently uses `pytest>=9.0.3`. Research confirmed that downgrading to `pytest>=8.4,<9` resolves this cleanly -- all 459 existing tests pass with pytest 8.4.2.

**Primary recommendation:** Downgrade pytest to `>=8.4,<9` in `pyproject.toml`, add `pytest-textual-snapshot>=1.1.0` to dev dependencies, build FakeBackend adapters as reusable test fixtures conforming to Protocol contracts, and create snapshot tests using `snap_compare` with `run_before` callbacks to reach each target screen state.

### Pattern 1: FakeBackend Adapter (Constructor Injection)

**What:** Test doubles conforming to Protocol contracts from `ports.py`, injected via widget/app constructor instead of `@patch`.

**When to use:** All Phase 20 widget tests. This is the Phase 18/19 architectural pattern -- dependency flows through the composition root.

**Example:**
```python
# Source: Pattern established in test_pane_coordinator.py (existing codebase)
from joy.ports import StoragePort, TerminalPort
from joy.models import Config, Project, Repo, TerminalSession

class FakeStorage:
    """Fake StoragePort for widget tests -- returns canned data, tracks calls."""
    def __init__(self, projects=None, config=None, repos=None):
        self.projects = projects or []
        self.config = config or Config()
        self.repos = repos or []
        self.saved_projects: list[list[Project]] = []

    def load_projects(self) -> list[Project]:
        return self.projects

    def save_projects(self, projects: list[Project]) -> None:
        self.saved_projects.append(list(projects))

    def load_config(self) -> Config:
        return self.config

    def save_config(self, config: Config) -> None:
        pass

    def load_repos(self) -> list[Repo]:
        return self.repos

    def save_repos(self, repos: list[Repo]) -> None:
        pass

    def load_archived_projects(self):
        return []

    def save_archived_projects(self, projects) -> None:
        pass


class FakeTerminal:
    """Fake TerminalPort for widget tests -- no iTerm2 subprocess calls."""
    def __init__(self, sessions=None, live_tab_ids=None):
        self._sessions = sessions or []
        self._live_tab_ids = live_tab_ids or set()
        self.activated: list[str] = []

    def fetch_sessions(self):
        return (self._sessions, self._live_tab_ids) if self._sessions else None

    def create_tab(self, name):
        return None

    def activate_session(self, session_id):
        self.activated.append(session_id)
        return True

    def close_session(self, session_id, *, force=False):
        return True

    def close_tab(self, tab_id, *, force=False):
        return True

    def create_session(self, name):
        return None

    def rename_session(self, session_id, new_name):
        return True
```

### Pattern 3: Snapshot Test with run_before

**What:** Using `snap_compare` with a `run_before` async callback to reach the desired screen state before capturing the SVG.

**When to use:** All snapshot tests (TEST-05). The callback loads fake data and navigates to the target state.

**Example:**
```python
# Source: pytest-textual-snapshot README (https://github.com/Textualize/pytest-textual-snapshot)
from unittest.mock import patch
from joy.app import JoyApp
from joy.models import Config, Project, ObjectItem, PresetKind

def _mock_store():
    """Patch store module functions to return canned data."""
    projects = [
        Project(name="project-alpha", objects=[
            ObjectItem(kind=PresetKind.BRANCH, value="main"),
            ObjectItem(kind=PresetKind.MR, value="https://pr/1", label="MR #1"),
        ]),
        Project(name="project-beta", objects=[]),
    ]
    return patch.multiple(
        "joy.store",
        load_projects=lambda: projects,
        load_config=lambda: Config(),
        load_repos=lambda: [],
    )

def test_initial_render(snap_compare):
    """Snapshot: initial render with project list loaded."""
    with _mock_store():
        assert snap_compare(JoyApp(), terminal_size=(120, 40))

def test_project_selected(snap_compare):
    """Snapshot: project selected, detail pane populated."""
    async def run_before(pilot):
        await pilot.pause(0.3)
        await pilot.app.workers.wait_for_complete()
        await pilot.press("enter")
        await pilot.pause(0.1)

    with _mock_store():
        assert snap_compare(JoyApp(), run_before=run_before, terminal_size=(120, 40))
```

### Anti-Patterns to Avoid

- **Using @patch for widget tests:** The whole point of Phase 20 is to replace `@patch("joy.store.load_projects", ...)` with FakeBackend constructor injection. Do NOT write new tests with `@patch` for store/service isolation.
- **Testing the full JoyApp for individual widget behavior:** Use minimal test app wrappers for widget behavior tests. Reserve JoyApp for snapshot tests where the full layout is the subject.
- **Snapshot tests that rely on timing:** Use `await pilot.pause()` and `await app.workers.wait_for_complete()` to ensure deterministic state before capture. Flaky snapshots from timing issues are worse than no snapshots.
- **Hardcoding terminal sizes inconsistently:** Pick one standard size (120x40 recommended) for all snapshot tests to ensure baselines are comparable.

## Common Pitfalls

### Pitfall 1: pytest-textual-snapshot requires pytest < 9
**What goes wrong:** Installing pytest-textual-snapshot 1.1.0 alongside pytest 9.x fails due to syrupy 4.8.0 requiring pytest < 9.
**Why it happens:** pytest-textual-snapshot pins `syrupy==4.8.0` (exact), and syrupy 4.x has pytest < 9 upper bound.
**How to avoid:** Downgrade pytest to `>=8.4,<9` in pyproject.toml. pytest 8.4.2 is the resolved version and passes all existing tests.
**Warning signs:** `uv pip install` error about incompatible pytest versions. [VERIFIED: local pip install dry-run confirmed conflict and resolution]

### Pitfall 2: Snapshot tests must use @patch for JoyApp store access
**What goes wrong:** Snapshot tests using `snap_compare(JoyApp())` call `JoyApp._load_data()` on mount, which calls `joy.store.load_projects()` etc. Without mocking, this reads from `~/.joy/` (or fails on missing files).
**Why it happens:** JoyApp's `on_mount` calls `_load_data()` which does lazy imports from `joy.store`. The store isolation fixture uses session-scoped patching of path constants, but the actual `load_projects()`/`load_config()` functions still execute real file I/O.
**How to avoid:** For snapshot tests, use `@patch` on the store module functions to return deterministic test data. The FakeBackend pattern is for widget-level tests; snapshot tests of the full app still need store mocking since JoyApp doesn't accept injected backends. This is an acceptable pragmatic choice.
**Warning signs:** Snapshot tests that produce different SVGs on different machines (because `~/.joy/` contents differ).

### Pitfall 3: Snapshot baseline divergence across environments
**What goes wrong:** SVG snapshots differ between macOS versions, terminal configurations, or font availability.
**Why it happens:** Textual renders SVG using Rich, which measures text differently depending on available fonts and terminal capabilities.
**How to avoid:** Pin terminal_size in all snapshot tests. Accept that snapshots are developer-local baselines initially (CI integration is deferred to ATEST-02). Run `--snapshot-update` to regenerate baselines when environment changes.
**Warning signs:** Snapshot tests that fail immediately after `git clone` on a new machine.

### Pitfall 4: Async worker timing in snapshot tests
**What goes wrong:** Snapshot captures before background workers complete, resulting in "Loading..." states instead of populated panes.
**Why it happens:** JoyApp uses `@work(thread=True)` for data loading; `snap_compare`'s `run_before` callback must explicitly wait for workers.
**How to avoid:** In `run_before` callbacks, always call `await pilot.pause(0.3)` followed by `await pilot.app.workers.wait_for_complete()` before asserting or capturing.
**Warning signs:** Snapshot baselines showing "Loading worktrees..." or empty panes.

### Pitfall 5: Existing test_worktree_pane.py and test_terminal_pane.py use asyncio.run() directly
**What goes wrong:** Some existing tests bypass pytest-asyncio by wrapping async code in `asyncio.run()`. This pattern is fragile and can conflict with pytest-asyncio's event loop management.
**Why it happens:** Historical pattern from Phase 9/12 before consistent pytest-asyncio usage was established.
**How to avoid:** New Phase 20 tests should use `@pytest.mark.asyncio` and `async def` consistently. Do not copy the `asyncio.run()` pattern from older tests.
**Warning signs:** `RuntimeError: This event loop is already running` when mixing patterns.

### Widget Test: ProjectList with FakeBackend

```python
# Source: Pattern derived from test_pane_coordinator.py (existing) + ports.py Protocols
import pytest
from textual.app import App, ComposeResult
from joy.models import Config, ObjectItem, PresetKind, Project, Repo
from joy.widgets.project_list import ProjectList, ProjectRow


def _sample_projects():
    return [
        Project(name="alpha", objects=[
            ObjectItem(kind=PresetKind.BRANCH, value="main"),
            ObjectItem(kind=PresetKind.WORKTREE, value="/wt/alpha"),
        ]),
        Project(name="beta", objects=[]),
    ]


class _ProjectListTestApp(App):
    def compose(self) -> ComposeResult:
        yield ProjectList(id="project-list")


@pytest.mark.asyncio
async def test_project_list_renders_rows():
    """ProjectList renders ProjectRow for each project."""
    app = _ProjectListTestApp()
    async with app.run_test() as pilot:
        plist = app.query_one(ProjectList)
        plist.set_projects(_sample_projects(), [])
        await pilot.pause(0.1)
        rows = app.query(ProjectRow)
        assert len(rows) == 2
```

## Open Questions

1. **Widget constructor injection for JoyApp**
   - What we know: Individual widgets (WorktreePane, TerminalPane, ProjectList, ProjectDetail) are composed inside JoyApp's `compose()` method without constructor-injected backends. Widgets receive data via method calls (`set_worktrees()`, `set_sessions()`, `set_project()`).
   - What's unclear: Should Phase 20 widget tests inject fakes at the widget level (testing set_worktrees/set_sessions directly) or at the app level (testing the full data flow from load to display)? 
   - Recommendation: Test both layers -- widget-level tests use direct method injection (call `set_worktrees()` with fake data); snapshot tests use store-level patching for full app rendering. This matches the existing pattern in `test_terminal_pane.py`.

2. **Handling the one pre-existing test failure**
   - What we know: `tests/test_refresh.py::test_terminal_load_on_mount` fails (expects SessionRow but gets 0). This is a pre-existing issue unrelated to Phase 20.
   - What's unclear: Should Phase 20 fix this or exclude it?
   - Recommendation: Exclude (`--ignore=tests/test_refresh.py` or `xfail` marker) -- this test failure is pre-existing tech debt, not Phase 20 scope. TEST-06 in Phase 19 may have already addressed some tech debt.

3. **Snapshot test marker configuration**
   - What we know: The project uses `@pytest.mark.slow` for existing pilot tests and excludes them from default runs via `-m "not slow and not macos_integration"`.
   - What's unclear: Should snapshot tests also use `@pytest.mark.slow` or get a new marker?
   - Recommendation: Add a `snapshot` marker and exclude it from default runs alongside `slow`. Snapshot tests are typically slower than unit tests and generate/check baseline files.
