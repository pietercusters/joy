The class needs:

1. __init__: State:
   - `self._worktrees_ready: bool = False`
   - `self._sessions_ready: bool = False`
   - `self._rel_index: RelationshipIndex | None = None`
   - `self._current_worktrees: list[WorktreeInfo] = []`
   - `self._current_sessions: list[TerminalSession] = []`
   - `self._current_mr_data: dict = {}`
   - `self._current_mr_authored: list = []`

2. Properties for read access:
   - `rel_index` -> RelationshipIndex | None
   - `current_worktrees` -> list[WorktreeInfo]
   - `current_sessions` -> list[TerminalSession]
   - `current_mr_data` -> dict
   - `current_mr_authored` -> list

3. `mark_worktrees_ready(self, worktrees, mr_data, mr_authored)`:
   - Stores worktrees, mr_data, mr_authored
   - Sets `_worktrees_ready = True`

4. `mark_sessions_ready(self, sessions)`:
   - Stores sessions
   - Sets `_sessions_ready = True`

5. `maybe_compute_relationships(self, projects, repos) -> RelationshipIndex | None`:
   - If not (worktrees_ready AND sessions_ready): return None
   - Reset both flags to False
   - Call compute_relationships(projects, worktrees, sessions, repos)
   - Store result in self._rel_index
   - Return the index

6. `propagate_mr_auto_add(self, mr_data, projects, config) -> list[str]`:
   - EXACT same logic as current _propagate_mr_auto_add (lines 358-394)
   - Pure function: takes mr_data dict, projects list, config (for default_open_kinds)
   - Returns list of notification message strings
   - Mutates project.objects in place (appending new MR ObjectItem)

7. `heal_stale_tabs(self, projects, sessions, live_tab_ids) -> list[str]`:
   - If sessions is None: return []
   - For each project: if iterm_tab_id not in live_tab_ids, clear it
   - Returns list of project names that were healed (for notification)

8. `compute_linked_worktree_sets(self, projects, worktrees) -> tuple[set[str], set[tuple[str, str]]]`:
   - EXACT same logic as _apply_worktree_link_status_fast (lines 426-446)
   - Returns (linked_paths, linked_branches) — no widget dependency

9. `build_tab_groups(self, projects, live_tab_ids) -> list[tuple[str, str]]`:
   - EXACT same logic as the tab_groups computation in _set_terminal_sessions (lines 322-326)
   - Returns list of (project_name, tab_id) tuples
